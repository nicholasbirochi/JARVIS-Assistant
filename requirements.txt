# transformers>=4.57,<5

# --- Empacotamento (opcional, comentado por padrão) ---
# Só pra src/scripts/build_app.py, nunca importado em runtime. O modo
# "alias" do py2app é a correção real de um bug de verdade: o python@3.12
# do Homebrew é uma build "framework" do macOS, e o próprio código C de
# startup do CPython reexecuta silenciosamente pra dentro de
# .../Resources/Python.app/Contents/MacOS/Python sempre que não está
# rodando já como esse binário exato (confirmado via `strings` no próprio
# interpretador -- incondicional, compilado, não é algo que uma env var
# desliga). Essa troca muda a identidade do processo de
# com.nicholasbirochi.jarvis pra org.python.python genérico, que foi
# exatamente o que quebrava o NSStatusItem (o ícone da barra de menu nunca
# aparecia -- confirmado ao vivo via Console.app: "AppKit:StatusBar] scene
# activation failed" em todo double-click real). O modo alias constrói um
# .app de verdade cujo próprio stub compilado é dono dessa identidade desde
# o início, continuando a rodar direto do código-fonte/venv deste projeto
# -- sem congelar, sem empacotar dependências junto. Descomente pra usar:
# py2app>=0.28
